# 世界 BOSS 策划文档

> **Status:** approved  
> **实施计划：** [`2026-10-09-world-boss.md`](2026-10-09-world-boss.md)

**For agentic workers:** 本期在可分线的世界 BOSS 图里刷多只 BOSS 和小怪。击杀奖励按正式组队区分单独与组队，另加伤害前三和最后一击。组队的创建、邀请和离队见 [`2026-10-09-party-design.md`](2026-10-09-party-design.md)，本文件只消费队伍名单。沿用现有怪物心跳和自动分线。不改 `Cast` / `ApplyBuff` 签名，不做客户端。

---

## 背景与目标

怪物已经能追击、出手和复活，但击杀没有归属和奖励，也没有队伍。玩家需要一张可分线的图，单独打死 BOSS，或组队打死怪，拿到不同的奖。

**一期目标：** 地图 4 每一条线都有多只 BOSS 和小怪。正式组队后，同队至少两人出力才拿组队参与奖；只有一人出力拿单独参与奖。伤害前三和最后一击另发，可与参与奖叠加。背包放不下的进待领取，不走邮件。

---

## 用户场景

1. 玩家从主城切到世界 BOSS（地图 4）。1 线未满进 1 线，满了进下一条。出生在 `(0,0,0)`。本线 `(20,0,0)` 和 `(-20,0,10)` 各有一只荒原霸主，`(8,0,8)` 有 4 只狼群。另一条线的怪互不影响。
2. 一名玩家单独把一只霸主打死，拿到单独参与奖 20 个铜币袋。他的伤害是第 1，并且是最后一击，再拿 30 个铜币袋和 5 瓶药水。
3. 队长邀请 3 名已进场的玩家，对方 30 秒内接受。其中 2 人在本线打过同一只狼，怪物死亡时两人都还在本线，每人拿 1 个铜币袋。只打过一刀、但不在这支队伍里的路人没有参与奖。
4. 伤害前三里，第 2 名已经断线，不发奖；第 3 名还在本线但已经死亡，仍然发放。背包满了的条目进待领取，之后 `game.reward.take` 再拿。

---

## 功能范围

### 包含

- 地图 4「世界BOSS」：可战斗，每线 30 人，3 条线，出生点 `(0,0,0)`，切图冷却 10 秒
- 怪物模板增加 `kind`：`boss` 或 `mob`
- 刷怪点 `line=0` 时，该图每一条已开放的线都刷同样的点；写了具体线号则只刷那一条
- 击杀归属读取 [`2026-10-09-party-design.md`](2026-10-09-party-design.md) 的队伍名单。本文件不另做邀请和离队
- 每只怪物每一条命记录实际扣血、达到该伤害的时间、最后一击
- 奖励表 `kill_reward`，按怪物和种类发放单独、组队、前三、最后一击
- 背包放不下时写入 `player_reward_claims`，再由 `game.reward.list` / `game.reward.take` 领取
- 结算推送 `onKillSettle`

### 不包含

- 手动选线、跨服、BOSS 阶段技能、仇恨列表
- 掉落物掉在地上、掷骰、拍卖、全服公告、正式邮件
- 修改 `Cast` / `ApplyBuff` 的参数
- 客户端

## 协议设计

切图仍用现有 `game.player.switchScene`，不传线号。

| 类型 | Route / 事件 | 请求 | 响应 / Push | 说明 |
|------|----------------|------|-------------|------|
| RPC | `game.reward.list` | `Empty` | `RewardListResponse` | 当前角色的待领取 |
| RPC | `game.reward.take` | `RewardTakeRequest` | `RewardTakeResponse` | 领取一条待领取 |
| Push | `onKillSettle` | — | `KillSettle` | 推给本线相关玩家，不看 AOI |

组队路由、`PartyState` 和错误码 `40060`–`40065` 见 [`2026-10-09-party-design.md`](2026-10-09-party-design.md)。

`KillSettle` 带怪物实例 uid、模板 id、归类（`solo` / `party` / `open`）、自己的名次（没有名次为 0）、最后一击者 uid，以及自己这次拿到的道具和数量。道具进背包还是进待领取，用条目上的标志区分。

`RewardTakeRequest` 带待领取 id。成功响应带该条已删除后的背包变化。

**业务错误码草案：** 领取时背包已满沿用 `40022`。未进场沿用 `40009`。组队错误码不在本文件。

**前置条件：** 领奖要已进场。击杀结算不依赖新的战斗路由。队伍名单来自组队策划。

## 数据与持久化

| 表 / 缓存 | 字段 / Key | 索引 / TTL | 说明 |
|-----------|------------|------------|------|
| `cfg_scene` 新增一行 | id=4、name、allow_combat、max_online=30、max_lines=3、出生点、switch_cd_ms=10000 | 主键 id | 可战斗 |
| `cfg_monster.kind` | `boss` 或 `mob` | 主键 id | 空值或其它值的行不生成 |
| `cfg_spawn.line` | `0` 表示该图每一条线 | 主键 id | 大于 0 时仍只刷那一条 |
| `cfg_kill_reward` | id、monster_id、kind、item_id、count | 主键 id；monster_id + kind 唯一 | kind 为 `solo`、`party`、`rank1`、`rank2`、`rank3`、`last` |
| `player_reward_claims` | id、player_id、item_id、count、reason、monster_id、created_at | 主键 id；player_id 索引 | 背包满时的待领取。领取成功后删除 |
| 进程内存 | 每只怪物这一条命的伤害和时间、最后一击 | 怪物复活清空 | 队伍和邀请不在这里，见组队策划 |

**事务：** 配表导入沿用现有 import 单事务。进背包沿用现有背包事务。待领取的插入和领取成功后的删除放在同一事务里：先尝试进背包，失败再插入待领取；领取时先占住这条待领取，进背包成功再删除。伤害榜不落库。

**热更：** 地图、怪物、刷怪点和奖励表沿用 `game.config.reload`。`line=0` 的点在热更后按当时的分线数补齐或拆掉。已在打的那条命继续用刷出时的属性拷贝，奖励读死亡当时的奖励表。

**种子：**

| 对象 | 值 |
|------|----|
| 地图 4 | 世界BOSS，可战斗，每线 30 人，3 线，出生点 `(0,0,0)`，冷却 10000 毫秒 |
| 怪物 2 | 荒原霸主，`boss`，生命 5000，攻击 15，防御 5，移速 3，攻击距离 3，间隔 1500 毫秒，仇恨 10，回家 25 |
| 怪物 3 | 狼群，`mob`，生命 200，攻击 8，防御 2，移速 4，攻击距离 2，间隔 1200 毫秒，仇恨 6，回家 12 |
| 刷怪 | `line=0`，地图 4。霸主两行：`(20,0,0)`、`(-20,0,10)`，各 1 只，复活 300000 毫秒。狼群一行：`(8,0,8)`，4 只，复活 15000 毫秒 |
| 霸主奖励 | solo 铜币袋 20；party 每人 8；rank1/2/3 为 30/15/8；last 药水 5 |
| 狼群奖励 | solo 铜币袋 2；party 每人 1；rank1/2/3 为 3/2/1；last 药水 1 |

铜币袋是道具 `1002`，药水是道具 `1001`。荒野野狼的刷怪点仍写 1 线，不因为 `line=0` 的新规则改掉。

## 业务规则

- 切图沿用现有自动分线。伤害、怪物实例和发奖都不跨线，也不跨图。
- BOSS 和小怪都走现有追击、出手、禁手、防御减伤和回出生点复活。本期没有 BOSS 阶段技能。
- 每条命单独记账。实际扣掉的生命才计入伤害，溢出不算。持续伤害算在施加该 Buff 的玩家头上。复活时清空伤害和最后一击。
- 队伍名单以 [`2026-10-09-party-design.md`](2026-10-09-party-design.md) 的 Redis 记录为准。本文件只在怪物死亡时读取：谁和谁同队。结算时人必须还在死怪的那张图、那条线。跨服队友不在这条线上，就没有这次击杀的份。
- 怪物死亡时先归类，再发奖：
  - **单独击杀**：造成过伤害的玩家只有 1 人。他拿 `solo`。他在不在队伍里都一样。只有他自己的队伍不算组队。
  - **组队击杀**：同一支队伍里，至少 2 名成员都造成过伤害，并且结算时都还在本图本线。这几个人每人拿一份 `party`，不把一份奖拆开。
  - 两支队伍都合格时，造成过伤害且仍在本线的队员更多的那支获胜。人数相同，比这些队员的伤害合计。再相同，队伍 id 更小的获胜。另一支没有参与奖。
  - **公开争夺**：没有合格队伍，但有多名玩家造成过伤害。不发 `solo`，也不发 `party`。
- 路人的伤害不能帮一支队伍凑满 2 人。路人自己没有参与奖。
- 伤害前三和最后一击加在参与奖上面，同一个人可以叠拿。前三只在结算时仍在本图本线的玩家里排。伤害相同，先达到该伤害的人在前；仍相同则 uid 更小的在前。
- 最后一击是把生命打到 0 的那一下，技能和跳伤都算，拿 `last`。
- 断线或已经切走的人不发任何奖。人还在本线、只是已经死亡，可以领。
- 能进背包的直接进背包，并推 `onBagChange`。放不下的写入 `player_reward_claims`。领取时背包仍满，这条继续留着。
- `onKillSettle` 推给本线里造成过伤害、以及拿到奖的玩家。不靠 AOI。

## 验收标准

- [x] 切到地图 4 时人满进入下一条线，两条线各有两只霸主和 4 只狼，互不追击
- [x] 荒野野狼仍只在 1 线，不因 `line=0` 复制
- [x] 一人打死霸主拿到 solo、名次和最后一击；单人队伍仍算单独击杀
- [x] 同队两人出力且都在本线，每人拿到 party；路人没有参与奖
- [x] 两支合格队伍时，出力人数多的一支拿 party；人数相同比伤害合计
- [x] 多名无队伍玩家打死同一只怪时不发参与奖，前三和最后一击仍发
- [x] 伤害相同先达到者在前；断线的人不发奖；死在本线的人仍可领
- [x] 溢出伤害不进榜；复活后伤害清空
- [x] 背包满时写入待领取，腾出空位后 `take` 成功；仍满则待领取还在
- [x] `go test ./...` 通过
