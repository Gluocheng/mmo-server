# 装备 策划文档

> **Status:** approved  
> **实施计划：** [`2026-10-29-equipment.md`](2026-10-29-equipment.md)

**For agentic workers:** 本期让装备背包里的装备能穿到固定部位，并按战斗属性已有的公式加成生命、攻击、防御。穿脱放在独立的 `internal/gameapp/equip`，路由是 `game.equip.*`。背包只提供取出和放回，不认识部位。不改 `Cast` / `ApplyBuff` 签名，不做客户端。

---

## 背景与目标

战斗属性已经能算「基础 + 固定加成 + 百分比」，但加成只来自 Buff。道具表里有装备「新手木剑」，它只能躺在装备背包里，穿上不会改变攻击。

**一期目标：** 十二个部位各穿一件。穿上后，装备上的固定值和百分比进入同一套属性公式。脱掉或换下后加成消失。生命上限升高或降低的规则与属性 Buff 相同。

---

## 用户场景

1. 玩家已进场，装备背包里有新手木剑。穿到武器部位后，攻击从 10 变成 15。普攻系数 100%，打在防御 0 的人身上掉 15。视野里的人在下一拍 `onCombatFrame` 里看到攻击变化。
2. 武器部位已经有木剑，再穿另一把武器。新武器占住部位，旧武器回到刚腾出来的那个背包格。
3. 脱掉布衣。防御和生命上限回到没穿时的值。当前生命如果高于新上限，就压到新上限。装备背包已满时脱不下来，身上的衣服还在。
4. 两枚戒指分别穿在左戒指和右戒指上，攻击加成相加。戒指不能穿到武器上。

---

## 功能范围

### 包含

- 十二个部位：武器、副手、头盔、衣服、护腕、腰带、裤子、鞋子、项链、左戒指、右戒指、饰品。每个部位同时只能穿一件
- 装备背包格数从 8 改为 32。穿着不占这 32 格
- 道具表增加部位组。只有 `type=equipment` 且部位组合法的道具能穿
- 装备属性表：道具 id、属性名、固定值或百分比、数值。本期只允许 `hp`、`attack`、`defense`
- 独立模块 `internal/gameapp/equip`，路由 `game.equip.wear`、`game.equip.unwear`、`game.equip.equips`
- 穿脱后的背包变化走现有 `onBagChange`。自己另收 `onEquip`
- 穿着状态随背包内存一起脏标记、定时落库和断线落库
- 换装后立刻重算三项属性，交给现有战斗同步在下一拍推 `stats`
- 错误码 `40066`、`40067`

### 不包含

- 强化、镶嵌、耐久、套装、绑定改变、等级或职业限制
- 双手武器占用副手、外观
- 怪物穿装备
- 暴击、急速等未结算属性出现在装备上
- 新进程、客户端

---

## 模块边界

`internal/gameapp/equip` 自己管十二个部位、穿着内存、属性汇总和三条路由。游戏节点单独挂一个 equip Actor，按 uid 建子 Actor，和 bag、combat 并列。

背包不出现部位。它只导出两件事：从装备背包的某一格拿走 1 件，或把 1 件放回指定格、第一个空格。装备模块调用这两件事，再改自己的穿着。

战斗不出现道具 id。装备模块把当前穿着收成生命、攻击、防御的固定值和百分比，交给现有属性公式。下一拍仍由战斗同步推 `stats`。

穿脱成功后，背包格子和 `player_equipment` 仍进同一次落库。崩溃发生在这次落库之前时，库里的背包和穿着都还是旧的。

## 协议设计

路由在 `game.equip`，由该玩家的 equip 子 Actor 串行处理。不放进网关进场前白名单。

| 类型 | Route / 事件 | 请求 | 响应 / Push | 说明 |
|------|----------------|------|-------------|------|
| RPC | `game.equip.wear` | `EquipWearRequest` | `EquipState` | 从背包格穿到该道具配置的部位 |
| RPC | `game.equip.unwear` | `EquipUnwearRequest` | `EquipState` | 按部位脱下 |
| RPC | `game.equip.equips` | `Empty` | `EquipState` | 查询当前穿着 |
| Push | `onEquip` | — | `EquipState` | 只推给自己 |
| Push | `onBagChange` | — | 现有背包包 | 穿脱引起的背包格变化 |
| Push | `onCombatFrame` | — | 现有帧 | 三项属性变化走已有 `stats` |

`EquipWearRequest` 带 `bagType`、背包 `slot`，以及目标部位 id。本期只接受装备背包，种子里是 `bagType=4`。目标部位必须属于这件道具的部位组。组里只有一个部位时，目标部位 id 填 0，由配置决定。`EquipUnwearRequest` 带部位 id。

`EquipState` 按部位 id 顺序列出全部十二个部位。空部位的道具 id 为 0。每个已穿部位带道具 id，以及该道具的属性列表（属性名、`flat` 或 `percent`、数值）。

**业务错误码草案：**

| 码 | 常量 | 说明 |
|----|------|------|
| 40066 | `EquipInvalid` | 该格不是装备，或道具没有合法部位 |
| 40067 | `EquipSlotInvalid` | 部位不存在，或不属于这件道具的部位组 |

背包格是空的沿用 `40021`。装备背包没有空格、旧装备回不去时沿用 `40022`。未进场沿用 `40009`。道具不在配表沿用 `40023`。

**前置条件：** 已进场。死亡也可以穿脱。属性在下一拍及之后的出手里生效。

## 数据与持久化

| 表 / 缓存 | 字段 / Key | 索引 / TTL | 说明 |
|-----------|------------|------------|------|
| `cfg_equip_slot` | id、name、group_id | 主键 id | 十二个部位。左戒指和右戒指的 `group_id` 相同 |
| `cfg_item.equip_slot` | 部位组 id，0 表示不能穿 | 主键 id | 仅装备使用。多数组只有一个部位 |
| `cfg_equip_attr` | id、item_id、stat、mode、value | 主键 id | `stat` 为 `hp` / `attack` / `defense`，`mode` 为 `flat` / `percent` |
| `player_equipment` | player_id、slot_id、item_id | 唯一 (player_id, slot_id) | 当前穿着。空部位不写行 |
| `cfg_bag_type` | id=4 的 `slot_count` 改为 32 | 主键 id | 只放未穿上的装备 |
| bag Actor 内存 | 与背包同一份脏标记 | 离线卸载时清空 | 穿脱不单独打库 |

**事务：** 配表导入沿用现有 import 单事务。穿着和装备背包的变更放进同一次背包 flush：先写背包 diff，再替换该角色的 `player_equipment` 行。崩溃发生在 flush 之前时，库里的背包和穿着都还是旧的，重进场不会丢道具，也不会复制一份。

**热更：** 沿用 `game.config.reload`。已经穿上的装备按新表重算属性。道具从配表消失时，这件仍穿在身上，但不再提供属性，脱下后不能再穿。已穿在已删除部位上的装备视为该部位仍占用，直到脱掉；新的穿戴不能再选这个部位。

**种子：**

| 对象 | 值 |
|------|----|
| 部位 | 1 武器、2 副手、3 头盔、4 衣服、5 护腕、6 腰带、7 裤子、8 鞋子、9 项链、10 左戒指、11 右戒指、12 饰品。10 和 11 的组 id 都是 10，其余部位的组 id 等于自己的 id |
| 背包 | 装备背包 `bag_type=4` 的格数改为 32 |
| 2001 新手木剑 | 部位组 1。攻击 `flat` +5 |
| 2002 布衣 | 装备，不可堆叠，背包类型 4，部位组 4。生命 `flat` +20，防御 `flat` +3 |
| 2003 铜戒 | 装备，不可堆叠，背包类型 4，部位组 10。攻击 `flat` +1 |

玩家基础攻击仍是 10。穿上木剑后攻击是 15。再挂固定攻击 +5 的 Buff，攻击是 20。两枚铜戒都穿上再加 2。百分比加在固定值合计之后，与属性策划的公式相同。

## 业务规则

- 只有装备背包里的一件装备能穿。数量必须是 1。消耗品、材料和任务道具不能穿。
- 穿上时从该背包格拿走这件，放入目标部位。该部位原来有装备时，旧装备放回刚空出来的这一格。
- 脱下时放进装备背包的第一个空格。没有空格则返回 `40022`，身上的装备不动，背包也不变。
- 十二个部位同时生效，加成相加。衣服不能穿到武器上。戒指可以穿在左戒指或右戒指，不能穿到别的部位。两枚戒指都穿上时，两行属性都计入。组里只有一个空位时，穿戴请求的目标部位填 0，就穿到那个空位；两个都空时填 0 则穿到 id 较小的一个。指定的部位已被占用时，按换装处理。
- 最终属性仍是 `(基础 + 全部固定加成) × (100 + 全部百分比) / 100`。固定加成和百分比都包含 Buff 与当前穿着。同一件装备上的多行属性分别累加。
- 生命上限变高时当前生命加上差额。变低时把当前生命压到新上限。死亡不掉装备，复活后仍穿着。
- 换装成功后立刻把新的装备加成交给战斗。战斗按现有同步规则，在下一拍把变化了的生命上限、攻击、防御推给视野内的玩家。这一拍即使没有伤害也要发。
- 离场再进场时，战斗单位用基础值重建，再立刻叠上当前穿着。怪物没有穿着。
- 未结算的属性名不能配在 `cfg_equip_attr` 上。导入时这种行失败，不让它静默变成 0。
- 查询 `equips` 不改背包，也不标脏。

## 验收标准

- [x] 穿上新手木剑后攻击为 15，普攻对防御 0 掉 15；脱掉后回到 10
- [x] 木剑与固定攻击 +5 的 Buff 同时存在时攻击为 20
- [x] 穿上布衣后生命上限加 20、当前生命加 20、防御加 3；脱掉后上限回落，当前生命不超过新上限
- [x] 部位已有装备时再穿，旧装备回到原背包格
- [x] 装备背包已满时脱下返回 `40022`，穿着不变
- [x] 两枚铜戒分别穿在左右戒指上，攻击再加 2；把铜戒穿到武器部位返回 `40067`
- [x] 把药水或空格拿去穿，返回 `40066`；部位 id 非法返回 `40067`
- [x] 断线重进后穿着还在，攻击与离开前一致
- [x] `go test ./...` 通过

## 风险与依赖

| 项 | 说明 |
|----|------|
| 依赖 | 背包内存与 flush、战斗属性公式、战斗同步的 `stats` |
| 迁移 | 新表 `cfg_equip_slot`、`cfg_equip_attr`、`player_equipment`。道具表增加 `equip_slot`，旧行默认 0。装备背包格数从 8 改为 32，已有第 9 格及以后的数据不会出现，因为旧上限是 8 |
| 兼容 | 新路由。旧客户端不穿装备时属性与现在相同 |
| 热更 | 穿着中的属性随配表变。已从配表删除的道具留在身上但没有加成 |
