# 战斗属性 策划文档

> **Status:** approved  
> **实施计划：** [`2026-10-09-combat-attr.md`](2026-10-09-combat-attr.md)

**For agentic workers:** 本期把生命、攻击、防御收成同一套「基础值 + 固定加成 + 百分比加成」。技能伤害改为攻击力百分比再减防御。属性名单按市面常见做法列全，其余属性只登记、不结算。不改 `Cast` / `ApplyBuff` 签名，不做装备，不做客户端。

---

## 背景与目标

玩家现在没有攻击和防御。普攻伤害写在技能表上，防御只在打到怪物时扣。Buff 只有 `dot`、`hot`、`stun`，不能给属性加成。

**一期目标：** 进战斗的单位都有生命、攻击、防御。Buff 可以给这三项加固定值或百分比。出手用最终攻击算出伤害，再减对方的最终防御。市面上常见的其它属性先记进名单，公式留空。

---

## 用户场景

1. 玩家攻击 10、防御 0，普攻系数为 100%。打在防御 0 的玩家身上仍掉 10。打在防御 2 的野狼身上仍掉 8。
2. 挂上固定攻击 +5 的 Buff 后，普攻对防御 0 掉 15，对野狼掉 13。Buff 到期后回到 10 和 8。
3. 挂上生命上限 +50 的 Buff，当前生命同时加 50。Buff 消失后上限回到 100，当前生命如果高于 100 就压回 100。

---

## 功能范围

### 包含

- 玩家基础攻击、防御写入 `cfg_combat_const`。生命仍用现有 `max_hp`
- 怪物继续用模板上的生命、攻击、防御作为基础值
- 统一公式：固定加成相加，再乘百分比
- 技能表增加 `factor`。普攻、范围斩改成按攻击力百分比结算，手感与现在相同
- Buff 效果 `attr`，可加成生命、攻击、防御的固定值或百分比
- 属性名单表：登记市面常见属性，本期只结算其中三项

### 不包含

- 装备、等级成长、主属性换算、属性落库
- 暴击、命中、躲闪、急速、穿透、吸血的实际结算
- 新战斗路由和客户端
- 修改 `Cast` / `ApplyBuff` 的参数

## 数据与持久化

| 表 / 缓存 | 字段 / Key | 索引 / TTL | 说明 |
|-----------|------------|------------|------|
| `cfg_combat_const` | 现有 `max_hp`，新增 `attack`、`defense` | 主键 id=1 | 玩家基础值。种子生命 100、攻击 10、防御 0 |
| `cfg_skill.factor` | 攻击力百分比 | 主键 id | 不填当作 0 |
| `cfg_buff` | 末尾增加 `stat`、`mode` | 主键 id | 仅 `effect=attr` 使用 |
| `cfg_stat` | id、name、allow_flat、allow_percent、settle | 主键 id | 上表那份名单。`settle=true` 的本期才参与公式 |
| 进程内存 | 单位基础三围、当前生命、Buff 实例 | 离场即删 | 不写 `players` |

**事务：** 配表导入沿用现有 import 单事务。战斗属性不落库。

**热更：** 沿用 `game.config.reload`。新挂的 Buff 读新表。已经挂上的仍用施加时的拷贝。玩家基础值在下次进场时重读。已经在场的怪物继续用刷出时的基础值。

**种子：**

| 对象 | 值 |
|------|----|
| 玩家 | 生命 100，攻击 10，防御 0 |
| 普攻 | `damage=0`，`factor=100`。对防御 0 掉 10，对野狼防御 2 掉 8 |
| 范围斩 | `damage=0`，`factor=80`。对防御 0 掉 8，对野狼掉 6 |
| 禁手 | `damage=0`，`factor=0` |
| Buff | 现有撕裂、愈合、禁手不填 `stat` / `mode`。另加一条固定攻击 +5、持续 5000 毫秒、1 层，用来验收加成 |

野狼和霸主的生命、攻击、防御种子不改。

## 业务规则

- 玩家基础值来自战斗常量。怪物基础值来自模板。进场或刷出时拷贝，离场丢掉。
- 每次出手前，用当时还没到期的 `attr` Buff 重算最终属性。到期的那一毫秒起不再计入。
- `最终 = (基础 + 固定加成之和) × (100 + 百分比之和) / 100`，向下取整。一层的加成是 `value × 层数`。不同 Buff 的固定值相加，百分比相加。
- 攻击和防御最低为 0。生命上限最低为 1。百分比之和低于 -100 时，攻击和防御为 0，生命上限为 1。
- 生命上限变高时，当前生命加上同样的差额。生命上限变低时，当前生命压到新上限。死亡清除全部 Buff，复活用基础生命上限回满。
- `出手值 = 技能伤害 + 攻击方最终攻击 × factor / 100`，向下取整。出手值大于 0 时减去防守方最终防御，至少为 1。玩家打玩家也减防御。出手值为 0 时造成 0，仍可挂 Buff。
- 怪物出手视为技能伤害 0、`factor=100`，用自己的最终攻击去减对方最终防御。
- `dot` 和 `hot` 仍是固定值乘层数，不看攻击，不看防御。`stun` 仍只禁止出手和喝药，不改属性。
- 名单里 `settle=false` 的属性可以写进 `cfg_stat`，挂到 Buff 上时返回 `40041`，不参与公式。

## 验收标准

- [x] 未挂 Buff 时，普攻对防御 0 掉 10，对野狼掉 8；范围斩对防御 0 掉 8，对野狼掉 6
- [x] 固定攻击 +5 后，普攻对防御 0 掉 15；Buff 到期后回到 10
- [x] 攻击百分比 +20 后，攻击 10 变成 12
- [x] 生命上限 +50 时当前生命加 50；Buff 消失后当前生命不超过基础上限
- [x] 伤害为 0 的禁手仍然是 0，并能挂上 Buff
- [x] 持续伤害不吃攻击和防御
- [x] 未开放结算的属性名不能挂成有效 Buff
- [x] `go test ./...` 通过

## 风险与依赖

| 项 | 说明 |
|----|------|
| 依赖 | 现有战斗心跳、技能命中、Buff 施加和怪物攻击 |
| 迁移 | 战斗常量和技能表加列。旧技能不填 `factor` 时仍按原伤害，种子会改普攻和范围斩 |
| 兼容 | 无新路由。防御为 0 时，玩家互打和狼打人的数字与现在相同 |
| 后续 | 暴击、急速等只在 `cfg_stat` 登记。要结算时再打开 `settle`，不另做一套加成 |
