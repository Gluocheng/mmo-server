# 战斗禁手 策划文档

> **Status:** approved  
> **实施计划：** [`2026-10-08-combat-control.md`](2026-10-08-combat-control.md)

**For agentic workers:** 本期只在战斗框架内部增加控制效果。不改 `Cast` / `ApplyBuff` 签名，不做客户端。

---

## 背景与目标

技能和药水已经能结算，但没有控制。禁手不能写在背包或施法路由里。

**一期目标：** 配表效果 `stun` 表示禁手。效果还在时不能放技能，也不能对自己挂新 Buff。已经进下一拍队列的技能在结算时丢掉。

---

## 用户场景

1. 被点名技能命中后挂上禁手，这段时间放技能和喝药都失败，移动不受影响。
2. 禁手到期后可以再放技能。
3. 技能已经入队，结算前被禁手，这一拍不再造成伤害，冷却不退回。

---

## 功能范围

### 包含

- Buff 效果 `stun`：只要求持续时间大于 0，心跳不跳数值
- `Cast` 与 `ApplyBuff` 在禁手时返回 `40055`，不入队、不进冷却、不挂新 Buff
- 结算时施法者已死、已禁手或地图禁战，丢掉该意图
- 种子：一条禁手 Buff，一条伤害为 0 的点名技能，命中挂上它
- 错误码 `40055`

### 不包含

- 禁止移动
- 阵营、怪物、客户端
- 修改 `Cast` / `ApplyBuff` 的参数

---

## 协议设计

| 类型 | Route / 事件 | 请求 | 响应 / Push | 说明 |
|------|----------------|------|-------------|------|
| RPC | `game.combat.cast` | 不变 | 业务码 `40055` | 禁手时拒绝 |
| RPC | `game.bag.use` | 不变 | 业务码 `40055` | 因为 `ApplyBuff` 被拒绝，不扣道具 |

**业务错误码草案：** `40055 CombatStunned` — 身上有未到期的禁手。

**前置条件：** 已进场。打到身上的技能仍走框架内部挂 Buff，所以禁手可以被别人施加，也能被后续命中刷新。

---

## 数据与持久化

| 表 / 缓存 | 字段 / Key | 索引 / TTL | 说明 |
|-----------|------------|------------|------|
| `cfg_buff` | effect=`stun` | 主键 id | 数值可为 0 |
| `cfg_skill` | buff_id 指向禁手 | 主键 id | 伤害 0 |

**事务：** 不落库。热更后新挂的禁手读新表，已挂上的仍用施加时的拷贝。

**种子：** 禁手持续 2000 毫秒、间隔 0、数值 0、1 层。点名技能距离 3、冷却 5000 毫秒、伤害 0。

---

## 业务规则

- 禁手不造成伤害或治疗。
- 入队时已经开始的冷却，结算被丢掉后不退回。
- 死亡会清掉身上的 Buff，包括禁手。

---

## 验收标准

- [x] 禁手期间 `Cast` 和 `ApplyBuff` 返回 `40055`
- [x] 到期后可以再放技能
- [x] 禁手心跳不改变生命
- [x] 点名技能命中后目标被禁手
- [x] 入队后被禁手，下一拍不造成伤害
- [x] `go test ./...` 通过

---

## 风险与依赖

| 项 | 说明 |
|----|------|
| 依赖 | 已有心跳与 `ApplyBuff` |
| 迁移 | 只增加配表行，需重新导表后技能才存在 |
| 兼容 | 无新路由。旧客户端不放这条技能则无行为变化 |
