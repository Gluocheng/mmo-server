# 功能压测记录

压测指多连接打到正在运行的集群（网关 WebSocket 或 GM HTTP），并记录耗时、错误率和资源。单测、`Benchmark`、一两个客户端走通都不算压测。压测客户端和集群都在 Docker Compose 网络内，入口为 `gate-entry:10100`，见 `.cursor/rules/load-test-docker.mdc`。

全链路指少量真实客户端打到正在运行的集群，走完该功能的玩家路径。单测和进程内合包不算。

**压测是否通过：** `未压测` · `进行中` · `通过` · `未通过`

**全链路是否测过：** `未测` · `已测`

**全链路是否通过：** 未测填 `—`；已测填 `通过` 或 `未通过`。只表示记录里的那次路径走通，不表示压测场景里的并发或满员分支也走通。

## LT-02 记录

2026-10-08，提交 `10b7e20`，入口 `ws://127.0.0.1:10100`（gate-entry，后面是 gate-1 / gate-2 和 login-1 / login-2）。50 个新账号先签发，再分四段同时打。

- 同时 `gate.user.login`：50 个全部成功，墙钟 60 毫秒，p50 41 毫秒、p95 57 毫秒、最大 57 毫秒。
- 同时 `gate.user.refreshToken`：50 个全部成功，墙钟 76 毫秒，p50 52 毫秒、p95 68 毫秒、最大 69 毫秒。
- 同时用刷新前的旧 refresh 再刷一次：50 个全部是 `40013`（RefreshTokenReplay），墙钟 45 毫秒。
- 同一条已登录连接上同时 `gate.user.logout`：50 个客户端都在 2 秒超时，没有收到回包。超时后立刻用刚才的 access 再登录，50 个全部是 `40011`，说明令牌已经被吊销，登出在服务端做完了，回包被丢掉了。

丢包原因：网关 `logout` 先 `Unbind` 把连接从会话表删掉，再 `Response`。回包按 sid 找连接，这时已经找不到，客户端就一直等到超时。

同一天改成先把回包放进这条连接的发送队列，再 `Unbind`，并重启两个网关后复测：50 个登出全部收到回包，墙钟 261 毫秒，p50 212 毫秒、p95 222 毫秒、最大 226 毫秒。随后用原 access 再登录，50 个全部是 `40011`。
