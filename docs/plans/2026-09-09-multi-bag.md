# 多背包系统 实施计划

> **Status:** done
> **Design:** [`2026-09-09-multi-bag-design.md`](2026-09-09-multi-bag-design.md)（**Status: approved**）
> **For agentic workers:** 按任务勾选推进；完成后更新 `docs/plans/README.md` 总览表。

**硬性顺序：** 策划文档 `approved` 后方可创建本文件并写业务代码。任务从策划的协议/数据/验收派生，勿重复长篇策划正文。

**Goal:** 为背包引入配置驱动的 `bag_type` 维度，道具按配置自动路由进对应背包，多背包 slot/缓存隔离。

**Architecture:** `inventory_items` 加 `bag_type(int32)` 列，唯一索引改 `(player_id, bag_type, slot)`；gameconfig 新增 `bag_type` 表 + `item.bag_type` 字段；`add` 自动路由 + 严格类型校验（`40028`）。

**Tech Stack:** Go / Cherry Actor / Protobuf / GORM / Redis / gameconfig(Luban)

## 备注

- 迁移时机陷阱已确认：`migrateInventorySlots` 在 gameconfig 加载前执行，无法用 runtime 解析 `item_id → bag_type`，故统一回填 `通用背包(1)`。
- 唯一索引变更需显式 drop 旧 `idx_player_slot`（`AutoMigrate` 不会自动删）。
- Luban 环境不可用（无 `Luban.ClientServer.dll`、无 dotnet），gen/cfg 与 gen/data 为手工维护，符合生成文件头注释约定。
