# 组队 实施计划

> **Status:** planned  
> **Design:** [`2026-10-09-party-design.md`](2026-10-09-party-design.md)（**Status: approved**）  
> **For agentic workers:** 按任务勾选推进；完成后更新 `docs/plans/README.md` 总览表。步骤用 `- [ ]` 跟踪。

**硬性顺序：** 策划已 approved。任务从策划的协议、数据和验收派生。不发世界 BOSS 奖励，不做客户端，不新开组队进程。

**Goal:** 已进场的玩家可以组建最多 4 人的队伍；名单在 Redis，不同游戏节点看到同一份；断线后席位保留 60 秒，时限内重新进场回到原位。

**Architecture:** `game.party` 子 Actor 处理本节点请求，Redis 保存队伍、邀请和在线节点。名单变化后按 `party:online:{uid}` 用 NATS 调用目标游戏节点的 `deliver`，该节点只推给自己进场表里的人。

**Tech Stack:** Go / Cherry Actor / Protobuf / Redis

## Global Constraints

- 队伍按账号 uid，上限 4 人，一人同时只在一支队伍。
- 邀请 30 秒；断线宽限 60 秒，宽限内仍占名额，原加入顺序不变。
- 切图、换线不离队，不写 `graceUntil`。
- 错误码 `40060`–`40065`；未进场仍是 `40009`。
- 队伍 id、邀请 id 用游戏节点雪花 `cherrySnowflake.NextID()`。
- 推送失败不回滚 Redis。

### Task 2: Redis 名单

**Files:** `internal/persistence/party.go`、`party_test.go`  
用现有 miniredis。时间由参数 `now int64` 传入，测试不睡真实 60 秒。

**Produces:**

```go
func CreateParty(ctx context.Context, uid, partyID int64, nodeID string, now int64) (PartyState, int32)
func Invite(ctx context.Context, leader, target, inviteID, expireAt int64, now int64) int32
func Answer(ctx context.Context, uid, inviteID int64, accept bool, now int64) (PartyState, int32)
func Leave(ctx context.Context, uid, now int64) (left PartyState, rest PartyState, code int32)
func Kick(ctx context.Context, leader, target, now int64) (left PartyState, rest PartyState, code int32)
func PartyStateOf(ctx context.Context, uid, now int64) (PartyState, int32)
func BeginGrace(ctx context.Context, uid, now int64) error
func OnEnter(ctx context.Context, uid int64, nodeID string, now int64) (PartyState, bool, error)
```

`PartyState.Members` 按加入顺序。`graceUntil==0` 表示没有宽限。每次改名单前先把已过 `graceUntil` 的成员按离队规则摘掉。`party:{id}` 的更新用 Redis 事务或 Lua，一次写完队长和成员。键：`party:{id}`、`party:uid:{uid}`、`party:invite:{uid}`（TTL 30 秒）、`party:online:{uid}`。
