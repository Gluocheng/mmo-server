# 战斗同步 策划文档

> **Status:** approved  
> **实施计划：** [`2026-10-12-combat-sync.md`](2026-10-12-combat-sync.md)

**For agentic workers:** 本期只规定战斗结果推给谁、何时推全量、何时推变化。属性公式以 [`2026-10-09-combat-attr-design.md`](2026-10-09-combat-attr-design.md) 为准。战斗留在游戏节点进程内。不改 `Cast` / `ApplyBuff` 签名，不做客户端预演。

---

## 背景与目标

服务端已经在心跳里扣血，并用 `onCombatFrame` 把命中推给视野内的玩家，用 `onMove` 推坐标。进场时的附近列表只有位置和单位类型。人走进 15 格才互相看见时，没有战斗外观的出现和消失。Buff 到期、攻击或防御变化如果这一拍没有伤害，别人看不到。

**一期目标：** 服务端仍是唯一权威。进视野时发一次完整快照，之后只在心跳里推变化。自己的生命和三项属性不会因为合包截断而丢掉。

---

## 用户场景

1. 玩家切到荒野，附近有一只野狼。进场响应仍只有坐标。紧接着收到自己和这只狼的 `onCombatSnapshot`，上面有当前生命、生命上限、攻击、防御和 Buff。
2. 玩家往前走进狼的仇恨距离。狼的移动仍走 `onMove`。打中时 `onCombatFrame` 里带这一拍的序号、命中和目标当前生命。客户端用 `targetHp` 覆盖本地生命，不自己减。
3. 狼身上的攻击 Buff 到期，这一拍没有新的伤害。视野内的玩家仍收到一拍帧，里面是 Buff 卸下，以及攻击回到模板值。
4. 玩家走出 15 格。收到 `onCombatGone`，丢掉这只狼的生命和 Buff。再走进来，只收到一份新快照，不补中间错过的每一拍。

---

## 功能范围

### 包含

- 战斗结算继续留在游戏节点进程内，不新增战斗进程
- 推送 `onCombatSnapshot`、`onCombatGone`
- `onCombatFrame` 增加本拍序号、Buff 变化、三项属性变化
- 进场、切图、走进或走出 15 格时的快照和消失
- 合包超限时保留自己的生命、三项属性和自己的 Buff
- 只同步已结算的当前生命、生命上限、攻击、防御和 Buff

### 不包含

- 单独的战斗进程，或跨节点看同一场战斗
- 客户端预演、延迟补偿、断线重放完整战斗记录
- 修改伤害公式，或推送尚未结算的暴击、急速等属性
- 把生命塞进 `onMove` 或进场响应
- 新的战斗 RPC。`game.combat.cast` 仍只提交意图

## 协议设计

不新增 RPC。进场和切图响应的字段不增加。

| 类型 | Route / 事件 | 请求 | 响应 / Push | 说明 |
|------|----------------|------|-------------|------|
| Push | `onCombatSnapshot` | — | `CombatSnapshot` | 一个单位的完整战斗外观 |
| Push | `onCombatFrame` | — | `CombatFrame` | 这一拍的命中和变化。没有变化不发 |
| Push | `onCombatGone` | — | `CombatGone` | 离开视野，只有 uid |
| Push | `onMove` | — | `MoveBroadcast` | 保持现有坐标包 |

`CombatSnapshot` 带 uid、当前生命、生命上限、攻击、防御、是否死亡，以及 Buff 列表。每条 Buff 带 id、层数、到期毫秒。

`CombatFrame` 在现有命中和 `truncated` 之外增加：

| 字段 | 说明 |
|------|------|
| `tick` | 本游戏进程递增的拍序号。某一拍没有包时，下次序号会跳 |
| `buffs` | 这一拍的 Buff 变化。层数 0 表示卸下 |
| `stats` | 生命上限、攻击或防御变了的单位。带这三项最终值和当前生命 |
| `self` | 仅在 `truncated=true` 时带上。自己的当前生命、三项属性和完整 Buff 列表 |

命中字段不变：来源、目标、技能、Buff、数值、是否治疗、目标当前生命、是否死亡。

`CombatGone` 只有 uid。

**业务错误码草案：** 不新增。

**前置条件：** 观众已进场，并且人在本游戏节点。推送沿用该玩家进场时记下的网关路径。

## 数据与持久化

| 表 / 缓存 | 字段 / Key | 索引 / TTL | 说明 |
|-----------|------------|------------|------|
| 进程内存 | 拍序号、单位当前战斗外观 | 离场或删怪即删 | 不写 MySQL，不写 Redis |
| 现有房间坐标 | 场景、线、XZ | 离场即删 | 用来判断 15 格和同图同线 |

**事务：** 不落库。

**热更：** 不新增配表。合包上限仍读 `frame_event_cap`。心跳间隔仍读 `tick_ms`。

## 业务规则

- 服务端是唯一权威。客户端不回传生命，也不预演扣血。
- 战斗留在游戏节点进程内。心跳在本进程读坐标、改怪物位置，再经本节点已有的网关路径推送。不拆战斗进程。每个游戏节点只结算自己的图。以后某一张图要扩容，把这张图上的人和怪一起搬到新节点。
- 观众是同一游戏节点、同一张图、同一条线上的玩家。怪物不收包。跨节点、跨线不推。
- 距离用现有 AOI：XZ 平面小于等于 15 格。能看见出手者或受击者，就能看见这一下。
- 只同步已经结算的当前生命、生命上限、攻击、防御，以及身上的 Buff。属性怎么算见战斗属性策划。
- 快照每个时机发一次，不每拍发。时机是：进场或切图成功之后的自己和当时附近的每个单位；移动之后新进入 15 格的单位。进场响应本身不加战斗字段。
- 离开 15 格时发 `onCombatGone`。客户端丢掉该 uid 的生命和 Buff。自己不会收到自己的消失。
- 同一拍的顺序是：先 `onMove`，再对新进入视野的单位发 `onCombatSnapshot`，再发这一拍的 `onCombatFrame`。
- 没有命中、没有 Buff 变化、也没有三项属性变化时，不发 `onCombatFrame`。拍序号仍然增加，所以客户端会看到跳号。
- 跳号时不补演中间伤害。下一份快照，或命中里的 `targetHp`，直接覆盖该 uid 的本地生命。
- Buff 挂上、叠层、刷新或到期，各占一条变化。层数 0 表示卸下。死亡清 Buff 时，身上每一条都记成卸下。
- 生命上限、攻击或防御相对上一拍有变化时，`stats` 带上该单位的三项最终值和当前生命。只有当前生命因伤害变化时，用命中里的 `targetHp`，不再重复塞一份属性。
- 单包条数超过 `frame_event_cap` 时截断，并置 `truncated`。优先留下自己打出的和打到自己的。自己的当前生命、三项属性和自己的 Buff 列表放进 `self`，不参与截断。别人被截掉的变化，等下一次看得见的命中，或重新进视野的快照。
- 怪物复活、玩家复活若带来生命或 Buff 变化，走同一套帧。不另做复活包。

## 验收标准

- [x] 进场或切图后，自己和附近单位各有一份快照；进场响应里仍然没有生命
- [x] 走进 15 格收到一份快照；走出 15 格收到 `onCombatGone`；再走进来不补中间的拍
- [x] 命中里的 `targetHp` 覆盖本地生命。这一拍没有伤害但 Buff 到期时，仍能收到卸下和属性回退
- [x] 合包截断时，自己的生命、三项属性和自己的 Buff 仍在；另一条线或另一个游戏节点收不到这些包
- [x] 没有变化的拍不发 `onCombatFrame`，下一拍序号可以不连续
- [x] `go test ./...` 通过

## 风险与依赖

| 项 | 说明 |
|----|------|
| 依赖 | 现有心跳、AOI、`onCombatFrame`、`onMove`，以及战斗属性策划里的三项最终值 |
| 迁移 | 无新表。`CombatFrame` 只追加字段，旧客户端忽略不认识的字段 |
| 兼容 | 新推送。旧客户端不处理快照时，仍能靠命中里的 `targetHp` 看到扣血 |
| 进程 | 战斗不拆进程。扩容时按图搬节点，不按战斗功能拆进程 |
| 视野 | 15 格外不推变化。重新走进来以新快照为准，中间过程不补 |
